# Send approved scanner registry metadata to Data Vault

Local browser scans remain encrypted in the scanner vault. They do not upload automatically. JPG/PDF downloads are ordinary files. This connector accepts only a complete authorized registry snapshot: random document ID, state, MIME type, byte count and last updated time. It rejects filenames, document titles, personal information, images and PDFs. Legacy Vault source `docs` remains unchanged.

The receiver is the separate `docs_scan` source in the private Data Vault at `vault.freshywater.in.th`. Both services must be deployed before connecting them. The sender must reach the approved private ingress; do not share the network proxy's secret with the DMS or relax VPN policy. If Vercel cannot reach Vault, run the authorized publisher/bridge within the approved network.

1. Set the Vault server secret `VAULT_SOURCE_DOCS_SCAN` with permitted `fields` equal to `["state","media_type","byte_count","updated_at"]` and a unique random `ingestToken`. Do not set a read token. Preserve all existing source secrets. Register a tested server-side publisher that produces a complete metadata snapshot with a monotonic integer cursor per source; do not publish browser-local partial listings or empty placeholders.
2. Supply the same ingest secret as `SCAN_BRIDGE_VAULT_INGEST_KEY` to the bridge and a distinct random `SCAN_BRIDGE_PUBLISHER_KEY` to the bridge and publisher only. Each should be a random 32-byte or longer base64url value. Set `SCAN_BRIDGE_ENABLED=1` only after testing private reachability. Do not enter keys into client storage, URLs, or source code.
3. Vault **ระบบ → ทะเบียนสแกนเอกสาร** controls whether the feed may send. **ระงับ** stops subsequent preflight checks, so they send no record payload. **ปิดกั้น** also revokes the configured source credentials; to reconnect, rotate them before reactivating. The separate global API pause blocks all sources. The Vault validates the state again at ingress and checks the gate revision and source generation on the database write, rejecting interrupted or stale submissions. This cannot recall data already accepted before a stop.
4. With synthetic records only, verify that a disabled or unreachable Vault results in no POST, then try an authorized test while enabled. Check that a paused-then-reopened source declines stale submissions. Keep the source disabled until the signer, registry and permissions are verified.
